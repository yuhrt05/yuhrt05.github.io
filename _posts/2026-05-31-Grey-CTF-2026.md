## Crimewatch

### Solution

Đề bài cung cấp cho ta 3 file gồm `flag.py` và 2 ổ đĩa ảo với định dạng `QCOW2`  

`flag.py`
```python
#!/usr/bin/env python3
import hashlib
import sys

from cryptography.hazmat.primitives.ciphers.aead import AESGCM

NONCE = bytes.fromhex("6372696d65776174636821")
CIPHERTEXT = bytes.fromhex("cdbfdb28bb51036b488c7f0565868b404116aa941538b3b6b27c7133799192ce239c630ec9e267a8671a9f7578")
TAG = bytes.fromhex("51dfb4e13c0206af0cc875e9b04ecb0e")

HELP = '''Crimewatch

Answer the case questions, then pass the answers to this script.

1. Which TeleChat account or chat appears to be supplying the courier with vape stock?
2. What car plate number connected to the supplier's import method is recoverable from deleted image/cache evidence?
3. Which TeleChat contact appears to be the most recent buyer awaiting a delivery?
4. What coordinates identify the pickup point?

Answer format:
- TeleChat handles include the leading @
- Plate numbers are uppercase with no spaces
- Buyer must be lowercase plain text
- Coordinates use decimal latitude,longitude rounded to 2 decimal places

usage: flag.py <supplier> <plate> <buyer> <coordinates>
'''

def normalise(values):
    supplier, plate, buyer, coordinates = [v.strip() for v in values]
    if buyer != buyer.lower():
        raise ValueError("buyer must be lowercase")
    return [
        supplier.lower(),
        plate.replace(" ", "").upper(),
        buyer,
        coordinates.replace(" ", ""),
    ]

if len(sys.argv) != 5:
    print(HELP)
    sys.exit(1)

try:
    candidate = "|".join(normalise(sys.argv[1:]))
except ValueError:
    print("[-] Wrong case reconstruction")
    sys.exit(1)

key = hashlib.sha256(candidate.encode()).digest()
try:
    plaintext = AESGCM(key).decrypt(NONCE, CIPHERTEXT + TAG, None)
except Exception:
    print("[-] Wrong case reconstruction")
    sys.exit(1)

print("[+] " + plaintext.decode())
```

Đọc sơ qua `flag.py` thì thấy được ta phải đi tìm được 4 đáp án gồm

```
supplier
plate
buyer
coordinates
```

Sau đó script sẽ thực hiện ghép chuỗi ví dụ: `@abc|29A12345|john|10.12,106.55` và thực hiện `SHA256` của chuỗi đó để tạo `AES` key 32-byte. Cuối cùng là thực hiện `decrypt` bằng `AESGCM` với `ciphertext` đã có sẵn trong đó

Tiếp đến chúng ta quan sát hai file QCOW2 được cung cấp:

![image](/assets/images15/4.png)

- Một file khoảng 1.3GB
- Một file chỉ khoảng 1.1MB

Tiếp theo mình tiến hành convert 2 file này sang raw image bằng `qemu-img`

```
qemu-img convert -O raw a image_raw.img 
qemu-img convert -O raw b image2_raw.img
```

Sau khi convert:
- image_raw.img có kích thước khoảng 6GB
- image2_raw.img khoảng 18MB

Giải thích thêm một chút về việc vì sao file QCOW2 ban đầu chỉ khoảng 1.3GB nhưng sau khi convert sang raw lại thành gần 6GB là do `QCOW2` là định dạng `sparse/compressed image`. Nó không lưu toàn bộ nội dung ổ đĩa một cách trực tiếp mà chỉ lưu các `block` thực sự đang được sử dụng (used blocks). Các vùng dữ liệu trống hoặc toàn byte `0x00` sẽ không chiếm dung lượng thật trên disk. Do đó kích thước file ban đầu chỉ phản ánh lượng dữ liệu đã sử dụng bên trong máy ảo, chứ không phải kích thước logic thật của partition. 

Sau khi convert sang `raw` thì toàn bộ block của ổ đĩa sẽ được hiển thị đầy đủ, bao gồm cả các block trống. Vì vậy file raw cuối cùng sẽ có kích thước đúng bằng kích thước logic thật của `userdata partition`, trong trường hợp này là khoảng `6GB`

Tiếp nữa, mình tiến hành kiểm tra bằng `fdisk`

![image](/assets/images15/5.png)

Thấy được đối với `image2_raw.img`, `fdisk` đã nhận diện được `GPT partition table`, nghĩa là image này hoàn toàn không bị mã hóa ở `block level`. Tiếp theo, image chỉ chứa duy nhất một partition Linux có kích thước khoảng `16mb`. Các điều trên cho ta thấy được `image2_raw.img` nhiều khả năng chỉ là một `metadata partition` nhỏ dùng để lưu thông tin mã hóa thay vì chứa dữ liệu người dùng thực tế

Ngược lại đối với `image_raw.img` nặng tới 6gb mà không thấy sự xuất hiện của `partition table` hay `filesystem` nào cả khả năng cao đã bị mã hóa toàn bộ.

Tiến hành mở `image2_raw.img` bằng autopsy thì nhận thấy có các file như `encrypted_key`, `keymaster_key_blob`,... 

![image](/assets/images15/6.png)

Đến đây thì khá bế tắc rồi và AI cũng chỉ hướng mà toàn hướng sai. Nên mình quyết định tìm các nguồn uy tín trên mạng thì thấy được 1 bài đăng thỏa luận về [Mount qcow2 image created by Android emulator](https://stackoverflow.com/questions/49039315/mount-qcow2-image-created-by-android-emulator) trên `Stack Overflow`. Và có 1 điểm làm mình chú ý tại đây khá giống với challenge này

![image](/assets/images15/7.png)

Tóm tắt thì là từ `Android 10/11` trở đi Android chuyển sang sử dụng `File-Based Encryption` (FBE) kết hợp với `metadata encryption`. Khi đó `userdata partition` sẽ bị mã hóa hoàn toàn ở `block layer` bằng `AES-XTS`, khiến các công cụ như: autopsy, mount, fdisk mặc định không thể nhận diện được `partition table`, `ext4 superblock`,.... Đây cũng chính là hiện tượng xuất hiện ở `image_raw.img`, khi fdisk hoàn toàn không detect được bất kỳ `filesystem` hay `partition` nào dù image có kích thước tới 6GB

Rất may trong cuộc thảo luận đó có đề cập đến 1 repo github dùng để decrypt `Android Emulator userdata` image sử dụng `FBE`. Repo tại [ĐÂY](https://github.com/SlugFiller/fbe-decrypt). Và đây cũng là bước ngoặt của challenge, giờ thì làm theo hướng dẫn của repo và tiến hành decrypt image thôi

Script của tác giả sử dụng code cứng để tìm đến các file yêu cầu, nên mình sẽ tiến hành đổi tên sao cho phù hợp và tiến hành decrypt

```python
#!/usr/bin/env python3
BEGIN = b"BEGIN_REAL_ARTIFACT_flag.enc\n"
END = b"\nEND_REAL_ARTIFACT"

CHUNK = 1024 * 1024  # 1MB

def extract_stream(path, out="flag.enc"):
    found = False
    buffer = b""
    with open(path, "rb") as f:
        while True:
            chunk = f.read(CHUNK)
            if not chunk:
                break
            buffer += chunk
            if not found:
                s = buffer.find(BEGIN)
                if s != -1:
                    buffer = buffer[s + len(BEGIN):]
                    found = True
                else:
                    buffer = buffer[-len(BEGIN):]
                    continue

            e = buffer.find(END)
            if e != -1:
                blob = buffer[:e]

                with open(out, "wb") as wf:
                    wf.write(blob)

                print(f"[+] extracted {len(blob)} bytes -> {out}")
                return
            if len(buffer) > 10 * 1024 * 1024:
                buffer = buffer[-1024 * 1024:]

    print("[!] artifact not found")
extract_stream("mem_dump.dmp")
```

```python
from pathlib import Path
import hashlib
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

passphrase = b"fa317cdb5f898ad01089b5432464052def12721f7f30f5c13d0af1f8b03e5295"
blob = Path("flag.enc").read_bytes()

assert blob[:8] == b"Salted__"

salt = blob[8:16]
ct = blob[16:]

key_iv = hashlib.pbkdf2_hmac("sha256", passphrase, salt, 10000, 32 + 16)
key = key_iv[:32]
iv = key_iv[32:]

pt = unpad(AES.new(key, AES.MODE_CBC, iv).decrypt(ct), 16)
print(pt.decode())
```

### Solution

Script solve

```python
import random
import struct
from pathlib import Path
from PIL import Image, ImageDraw


def main():
    pcap_path = Path("grey_yuumi.pcapng")
    if not pcap_path.exists():
        print(f"[-] File not found: {pcap_path.name}")
        return

    data = pcap_path.read_bytes()
    off = 0
    raw_packets = []

    print("[*] Parsing PCAPNG tracking blocks...")
    while off + 12 <= len(data):
        typ, blen = struct.unpack_from("<II", data, off)
        if blen < 12 or off + blen > len(data):
            break

        if typ == 6:  # Enhanced Packet Block
            cap = struct.unpack_from("<I", data, off + 20)[0]
            pkt = data[off + 28 : off + 28 + cap]

            if len(pkt) >= 28:
                hlen = struct.unpack_from("<H", pkt, 0)[0]
                payload = pkt[hlen:]

                if len(payload) == 13:
                    raw_packets.append(payload)

        off += blen

    print(f"[+] Extracted {len(raw_packets)} valid mouse payloads.")

    if not raw_packets:
        print("[-] No matching 13-byte payloads found. Forcing fallback...")
        off = 0
        while off + 12 <= len(data):
            typ, blen = struct.unpack_from("<II", data, off)
            if blen < 12 or off + blen > len(data):
                break
            if typ == 6:
                cap = struct.unpack_from("<I", data, off + 20)[0]
                pkt = data[off + 28 : off + 28 + cap]
                if len(pkt) >= 28:
                    hlen = struct.unpack_from("<H", pkt, 0)[0]
                    payload = pkt[hlen:]
                    if 8 <= len(payload) <= 64:
                        raw_packets.append(payload)
            off += blen

    cur_x, cur_y = 0, 0
    events = []
    min_x, min_y = float("inf"), float("inf")
    max_x, max_y = float("-inf"), float("-inf")

    for r in raw_packets:
        try:
            btn = r[0]
            dx = struct.unpack_from("<h", r, 2)[0]
            dy = struct.unpack_from("<h", r, 4)[0]

            cur_x += dx
            cur_y += dy

            min_x = min(min_x, cur_x)
            min_y = min(min_y, cur_y)
            max_x = max(max_x, cur_x)
            max_y = max(max_y, cur_y)

            events.append((btn, cur_x, cur_y))
        except Exception:
            continue

    if not events:
        print("[-] Crashing: No coordinate tracks could be generated.")
        return

    padding = 100
    width = max(200, int(max_x - min_x) + (padding * 2))
    height = max(200, int(max_y - min_y) + (padding * 2))

    print(f"[+] Target Canvas dimensions: {width}x{height}")

    # Bảng màu có độ tương phản cực mạnh để phân biệt rõ ràng từng nét
    DISTINCT_COLORS = [
        (255, 0, 0),  # Red
        (0, 255, 0),  # Green
        (0, 0, 255),  # Blue
        (255, 255, 0),  # Yellow
        (255, 0, 255),  # Magenta
        (0, 255, 255),  # Cyan
        (255, 165, 0),  # Orange
        (128, 0, 128),  # Purple
        (0, 255, 128),  # Spring Green
        (255, 105, 180),  # Hot Pink
        (135, 206, 235),  # Sky Blue
        (240, 230, 140),  # Khaki
    ]

    im = Image.new("RGB", (width, height), "white")
    draw = ImageDraw.Draw(im)

    last_pos = None
    stroke_count = 0
    current_color = DISTINCT_COLORS[0]

    for btn, cx, cy in events:
        x = int(cx - min_x) + padding
        y = int(cy - min_y) + padding

        if btn > 0:
            if last_pos:
                draw.line([last_pos, (x, y)], fill=current_color, width=3)
            else:
                # Mỗi lần bắt đầu một nét mới (khi người vẽ hạ chuột xuống), đổi sang màu tiếp theo
                current_color = DISTINCT_COLORS[
                    stroke_count % len(DISTINCT_COLORS)
                ]
                draw.ellipse(
                    (x - 2, y - 2, x + 2, y + 2), fill=current_color
                )

                # Đánh dấu số thứ tự trực tiếp lên điểm bắt đầu của nét vẽ để nhìn bằng mắt
                draw.text(
                    (x + 5, y - 10),
                    str(stroke_count + 1),
                    fill=(0, 0, 0),
                )
                stroke_count += 1

            last_pos = (x, y)
        else:
            last_pos = None

    output_file = "stroke_order_indexed.png"
    im.save(output_file)
    print(
        f"[+] SUCCESS: Indexed stroke map generated -> {output_file}"
    )
    print(f"[*] Total standalone strokes identified: {stroke_count}")


if __name__ == "__main__":
    main()
```
